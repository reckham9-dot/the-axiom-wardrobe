# The Axiom — переход на проверенный косметический движок

Состояние: STAGING. Никакой файл из этой ветки пока нельзя автоматически устанавливать на рабочий сервер.

## Цель

- Сохранить установленный и работающий AxiomWardrobe 0.8.0 как владельца скинов, сайта, AuthMe offline UUID, MySQL и аур.
- Полностью выключить только `CosmeticEngine` AxiomWardrobe (3D renderer).
- Использовать проверенный HMCCosmetics (GPLv3, исходники HibiscusMC/HMCCosmetics) как рендерер косметической экипировки: голова, спина, рюкзаки и воздушные спутники.
- Не трогать AxiomBridge, EconomyShopGUI, EliteMobs, игровые балансы и аккаунты.
- После проверки в клиенте соединить управление через один `/wardrobe` и синхронизировать права владения из существующих `axiom_wardrobe_*` таблиц (без удаления таблиц и переноса денег).
- Для пользователя — один гардероб и один профиль; сами бинарные зависимости не объединять до успешной совместной проверки.

## Подтверждённые сторонние источники

- HMCCosmetics: https://github.com/HibiscusMC/HMCCosmetics (исходный код GPLv3)
- Ветка `remapped`, commit `92d9193f05f08d083c06be1f2597fc4016940b80`. Сборка в `.github/workflows/hmccosmetics-staging.yml`.
- HibiscusCommons: https://github.com/HibiscusMC/HibiscusCommons — **отдельная обязательная серверная зависимость**.
- Подтверждение поддерживаемой версии 1.21.11: https://voxel.shop/product/1879/hmccosmetics/updates
- Правила визуальных рюкзаков: https://docs.hibiscusmc.com/hmccosmetics%20remapped/cosmetics/Backpack/

**Важно:** исходный код под GPLv3 не включает автоматически права на сторонние платные пакеты моделей. Для первого теста используем только контент с ясной лицензией и правильным ресурспаком, без копирования платных ресурсов.

## Прежде чем тестировать на сервере

1. Убрать AxiomRigProbe JAR из `plugins` (пробный модуль больше не нужен).
2. Отозвать старые диагностические ZIP `AxiomWardrobe-Wings-*probe*`, `*0.9.7*`, `*0.9.8*`, `*0.9.9*` из сборщика ресурспаков после создания резервной копии.
3. У основного AxiomWardrobe оставить `skins.apply-enabled: true`, `cosmetics.render-enabled: true`, `cosmetics.custom-models-enabled: false`, `cosmetics.visual-preview-unsafe-enabled: false`. Ауры и сайт остаются рабочими.
4. На отдельной тестовой копии сервера проверить чистый запуск HMCCosmetics, HibiscusCommons и других заявленных разработчиком зависимостей на Paper 1.21.11.
5. Только потом добавить **одну готовую, корректно лицензированную** модель крыльев и один готовый головной убор. Перед первой установкой проверить пути в **итоговом** ZIP ResourcePackManager, а не только во входном архиве.
6. Проверить отображение при повороте, ходьбе, приседании, телепортации, перезаходе и со второго клиента; тесты через Creative и Survival (на Creative у HMCCosmetics есть особенности виртуальной экипировки).
7. После визуального теста — интеграция выбора на сайте и в `/wardrobe`. Не записывать одновременно в две базы без версионирования и защиты от циклов.

## Лицензирование

При модификации/распространении кода HMCCosmetics соблюдать GPLv3: сохранить авторство и лицензию, сделать исходный код соответствующей модифицированной сборки доступным и отметить изменения. Простое использование установленного плагина через публичный API не является копированием его исходников. Не объединять чужие платные модели и текстуры без разрешения.

## Реальный статус

Сборка на GitHub — проверка подлинной компиляции, а не гарантия клиентского рендера. Ни новый рендерер, ни совместимость с текущими данными AxiomWardrobe не считаются рабочими до тестов. Не менять существующую работающую версию до приёмки.
